# Syriac lesson PDFs — the score for the printable lesson

*Wroot Labs · Fable scoping session 2026-09-02 · status: PLAN, nothing built. Execution is
Sonnet work per §8. Companion to `SYRIAC-WEB-PLAN.md` (the build this extends; read its §§1, 3,
4, 6 first) and `SYRIAC-LANGUAGE-PILOT.md`. This scores item 1 of NEXT-SESSION.md's "two new
ideas" — the downloadable PDF per lesson. Item 2 (stroke order) is NOT here; it needs its own
session (NEXT-SESSION.md says why).*

**Where the needle is.** syriac.paleography.app is live: eleven lesson pages, a drill engine,
the scholar pages, all generated by `learn/tools/make_learn.py` from two sources per lesson —
`learn/syriac/LESSON-N.md` (the prose, G2-passed as prose) and `learn/syriac/drill/LNN.toml`
(the drill sidecar, verbatim-checked against the prose). Wilson's ask, in his words: *a
downloadable PDF per lesson — grammar notes up front, drills at the end, answers printed on the
back, so the sheet works closed-book, face-down, the way a paper worksheet would.*

**The one rule this plan exists to protect.** The PDF is the **fourth consumer** of the same two
sources (after the lesson page, the drill JSON, and the index line). Nothing in it is authored a
second time. If a sentence appears in the PDF it came out of `LESSON-N.md` through the same
renderer the web uses; if a drill item appears it came out of the compiled sidecar the web's
engine already consumes. The PDF cannot drift from the site because it has no source of its own.

**What this is NOT.** Not a typeset book (no LaTeX, no second markup). Not the whole-course
reader as a product — a course bundle falls out for free (§5) but is not designed for. Not
stroke-order or tracing worksheets (item 2). Not a change to the lesson prose or the sidecars.

## 1. What was measured before scoring (2026-09-02, this Mac)

One smoke test, kept in the scratchpad, settles the tool question with facts rather than taste:
a 20-line HTML page with a line of pointed Estrangela in Noto Sans Syriac, printed to PDF by the
installed Google Chrome (`--headless=new --print-to-pdf`, Producer `Skia/PDF m152`).

| question | answer |
|---|---|
| Does Syriac shape correctly (joins, RTL, vowel points placed)? | **Yes** — rasterised and looked at, not inferred |
| Are fonts embedded? | Yes, as **subsets** (`pdffonts`: `NotoSansSyriac-Regular` CID TrueType, emb+sub) |
| Does `break-before: right` force an odd page? | **No** — treated as `page`; 4 pages came back where 5 were asked for. **Duplex parity is the generator's job, not CSS's** (§3) |
| Cost of one render | ~45 s wall, cold start + Google Fonts over the network; ~10 s CPU |
| What is already installed | Chrome · `qpdf` · `pdfinfo`/`pdffonts`/`pdftoppm` (poppler) · `pandoc` · XeLaTeX/LuaLaTeX · `pypdf` on python3.11. **Not** installed: weasyprint, wkhtmltopdf, Playwright's Python/Node packages (only its cached browsers) |

**Ruled out, and why, so the next session doesn't re-open it:**
- **LaTeX (XeLaTeX/LuaLaTeX, or pandoc → LaTeX):** a second typesetting source for the same
  prose, a second font stack, a second place Syriac can render wrong. Breaks the one-rule.
- **weasyprint:** not installed; Pango/HarfBuzz via Homebrew is a heavy install on an 8 GB Mac;
  its CSS coverage is narrower than Chrome's for the *same stylesheet the site already uses*.
- **wkhtmltopdf:** unmaintained QtWebKit; complex-script shaping is exactly its weak spot.
- **Playwright:** the right upgrade if render time ever grates (one browser process for all 44
  renders instead of 44 cold starts), but it is a new dependency and v1 doesn't need it (§8).

**Chosen: headless Chrome, driven by a stdlib-only Python tool, merged with `qpdf`.** Zero new
dependencies; the print stylesheet is the site's own CSS plus a `@page` block; the renderer that
produces the lesson page produces the PDF's notes verbatim.

## 2. The shape of one lesson PDF

```
lesson-N.pdf
├── Part I  — NOTES          continuous pages; padded to an EVEN count
│     title · "what you'll be able to do" · Stage 0 · Stage 1 (read-along, with its
│     word tables and notes) · any reference table the lesson's study-only tracks
│     carry (vowel marks, L1/L5) · the lesson footer (sources, records, licence)
├── Part II — SHEETS         each sheet = exactly 2 pages: FRONT (questions) + BACK (answers)
│     Sheet 1  Vocabulary      Syriac → sound + meaning; meaning → Syriac
│     Sheet 2  New forms       (Lessons 2–10)  form → cell + gloss
│     Sheet 3  Half a line · One word
│     Sheet 4  Finish the line · The whole line · Our drills
└── Scorecard                1 page, front only — the learner's own record
```

Lesson 0 has no Stages; its sheets are **Letters** (22 rows: letter → name + sound), **Pairs &
Triples** (Syriac string → the letter names), and nothing else. That is the only structural
exception and it is driven by which tracks the sidecar declares, not by a special case in code.

**Why sheets, not one long worksheet.** "Answers on the back" only works if the back of a
physical sheet holds the answers *to that sheet's front*. A long worksheet spanning three sheets
puts sheet 1's answers on sheet 1's back, which the learner sees when they turn sheet 1 over to
continue — the closed-book property fails at every page turn. So the unit is the sheet, each
sheet is self-contained, and the generator guarantees front and back are consecutive pages with
the front on an odd page (§3).

**Why the notes stop where they stop.** `LESSON-N.md` carries Stages 2–4 and the "Drills (ours)"
block *with their answers inline in italics* — right for a document, wrong for a face-down
sheet. Part I therefore ends at the first `## Drills` / `## Stage 2` heading (Lesson 0: at `## Part
3`); everything after it is reconstituted as sheets from the **compiled sidecar**, which holds the
same items with their answers as data. ⛔ Never scrape the italic `*Answers:*` paragraphs — Lesson 7
has two of them where the others have three, and the sidecar is already the checked, structured
form of exactly this content. The cut heading is declared per lesson in the sidecar (`[print]
notes_end = "## Drills"`, default; L00 overrides) so `make_pdf.py` has no lesson numbers in it.

## 3. Paper mechanics — the part no web page has to think about

**Duplex parity.** With long-edge duplex printing, odd pages are fronts and even pages are backs.
Every sheet's FRONT must land on an odd page. Chrome won't do it (§1), so the generator does:
render Part I alone → `pdfinfo` page count → if odd, append one intentionally blank page ("this
page is blank so the worksheets print back-to-back") → then the sheets. Every lesson PDF is thus
an even number of pages before the scorecard, which is what makes the course bundle (§5) print
correctly too — concatenating even-length documents preserves parity. Single-sided printers still
work: the answers are simply the next page, which the learner turns face down.

**One side, one page — by construction, and checked.** A sheet side is *designed* never to
overflow: the generator chunks item lists at a cap per sheet type (vocabulary 16 rows, forms 12,
text items 10; a lesson with 24 vocabulary rows gets Sheet 1a and 1b, each a full sheet) and the
type sizes are fixed in `print.css`. Then it is *verified*: the sheets are rendered as one
document and `pdfinfo` must report exactly `2 × sheets` pages, on Letter **and** on A4. Any other
count fails the build with the lesson named. Overflow is a bug in the caps, never a "just let it
run onto the next page."

**Blanks.** Sidecar prompts already mark the gap as `<span class='blank'></span>` inside the
Syriac string. On paper that becomes a ruled gap: a fixed **3 em** for one-word items, **9 em**
for "finish the line" — fixed, not proportional to the answer, so the blank's width never leaks
the answer's length. Rules under Syriac writing are set at roughly twice the type's x-height;
Estrangela by hand needs room the printed line doesn't. Direction: the gap sits inside an
`unicode-bidi: isolate` RTL run, so it lands where the missing word would fall, right to left.

**Order.** The web engine shuffles; paper doesn't. Sheet items print in sidecar order, which is
lesson order, which is the order the verbatim check already blessed. Numbering is shared by front
and back so an answer is found by its number, not by re-reading the question.

**Two directions on the vocabulary sheet.** The engine's `vocabMeaning` track climbs recognize →
reversed → produce. The paper sheet does the same on one side, as two blocks: (A) Syriac given,
write the sound and the meaning; (B) meaning given, write the Syriac. Back: the full table once
(Syriac · transliteration · gloss), which answers both blocks.

**The scorecard** stays a page, last, front only, from the sidecar's compiled `scorecard` — the
same fields the web's copy-to-clipboard emits, so a paper learner's report and a web learner's
report are the same shape when either arrives by email.

**Page furniture.** A running footer on every page: *A Syriac Chrestomathy · Lesson N ·
syriac.paleography.app/lesson/N*, via a `position: fixed` element (Chrome repeats these per
printed page). Page numbers are wanted but not load-bearing: Chrome's support for `@page`
margin boxes is to be checked ONCE in Phase 0 and used if present, otherwise dropped — sheets are
already numbered and the notes are read in order. The PDF's document title comes from `<title>`.

**Page size.** Letter is Wilson's printer; A4 is every Syriacist's. The layout uses relative
units and no absolute positioning, so the same HTML renders to both by swapping the `@page` size.
Ship both: `lesson-N.pdf` (Letter) and `lesson-N-a4.pdf`. The overflow gate runs on both.

## 4. Fonts — one fact corrects the web plan

`SYRIAC-WEB-PLAN.md` §4 said "serve Meltho." **The build that shipped uses Noto Sans Syriac from
Google Fonts, not Meltho** (`learn/shell/lesson_shell.html`, line 14; no font files exist under
`learn/`). That was the right call for the web, and it is decisive here: a PDF *embeds a subset*
of every font it uses (§1), and Meltho's licence — redistribute yes, modify no — was never
resolved for subsetting (`research/syriac-pilot-phase0.md`, fonts row). **Noto Sans Syriac, EB
Garamond and IBM Plex Sans are all OFL**, and the OFL permits embedding and subsetting outright.
⛔ Meltho does not go into the PDF, ever, until someone reads its packaged licence text on this
exact point — and there is no reason to, since Noto is already the site's face.

For the build, the three faces are **self-hosted under `learn/fonts/`** (unmodified `.ttf` +
each family's `OFL.txt`, tracked; ~2 MB) and loaded by `file://` `@font-face` in `print.css`, so
a render needs no network and Google Fonts' serving choices can't change the PDF between builds.
The web keeps using Google Fonts; the two stylesheets name the same families, so what a learner
sees on screen and on paper is the same type.

## 5. Where the files live and how they are reached

- **Generated, into `learn/site/pdf/`** — `lesson-N.pdf`, `lesson-N-a4.pdf` for N = 0…10, plus
  `chrestomathy.pdf` / `chrestomathy-a4.pdf` = all eleven concatenated with `qpdf` (free, given
  §3's even-page invariant). Gitignored with the rest of `learn/site/`; the deploy root serves
  them as static files; nothing on Vercel needs configuring beyond the existing `Cache-Control`.
- **Not run on every build.** `make_learn.py` stays fast (it runs on every edit and in `--check`).
  The PDF pass is `make_pdf.py`, invoked separately (or via `make_learn.py --pdf`), because 44
  Chrome cold starts are ~10 minutes on this Mac. Its `--check` is what CI-style verification
  runs (§6); the full render is what a deploy runs.
- **Reached from** each lesson page (one line under the headnotes: *Print this lesson — PDF
  (Letter · A4)*), from `/` (one line for the course bundle), and from `/for-syriacists` (a
  scholar can read the whole course in one file without clicking eleven times — this is the
  cheapest thing the PDF does for the held outreach).
- **Rights line** on Part I's footer, from `SYRIAC-WEB-PLAN.md` §6 verbatim: sources public
  domain; lesson prose, drill data and encoding CC BY-NC 4.0; fonts OFL. Free, never paywalled,
  no gate (§7 ruling 5 of the web plan applies to a file exactly as to a page).

## 6. `make_pdf.py` — what it is, and what `--check` proves

`learn/tools/make_pdf.py`, stdlib only, **imports `make_learn` and `make_drill`** (never forks
them) to get: the lesson texts, `split_lesson_body`, `extract_record_refs`, the record footer,
`make_primers.render`, and `make_drill.build`'s compiled lessons. It adds three things —
`learn/shell/print.css`, a small set of sheet templates (one per sheet type, plain f-strings like
the rest of the tools), and the paper mechanics of §3 — and drives `chrome`, `pdfinfo`, `qpdf`
by `subprocess`.

Per lesson, per page size: (1) notes HTML → PDF → count → pad; (2) sheets HTML → PDF → count ==
2×sheets else FAIL; (3) scorecard HTML → PDF; (4) `qpdf` merge. Then the bundle.

**`--check` proves, without writing to `learn/site/`:**
1. every lesson's `[print] notes_end` heading exists in its `.md`, exactly once;
2. every Syriac string placed on a sheet occurs verbatim in the compiled sidecar — the PDF adds
   no Syriac (this inherits the sidecar's own verbatim-to-prose check transitively);
3. every sheet renders to exactly two pages on both sizes;
4. every notes part is even after padding, so every lesson PDF is even before its scorecard;
5. `pdffonts` shows `NotoSansSyriac` embedded in every lesson (the one way a font fallback
   would otherwise pass silently — Chrome substitutes without complaint);
6. the same record-id resolution the web footer already checks (ids in the footer exist).

`--check` renders, so it is slow; that is the price of checking the thing that matters (page
counts) rather than a proxy.

## 7. Phases, in order — each ends in something Wilson can hold

**Phase 0 — one lesson by hand, on paper (Sonnet; the paper G2, call it G3).** Fetch the three
OFL families into `learn/fonts/`. Write `print.css`. Hand-assemble **Lesson 2** (the median
lesson: 14 vocabulary rows, 6 forms, 18 text items, so every sheet type appears) as HTML using
the real renderer output and the real compiled sidecar, print it through Chrome, and check
margin-box page numbers once. **Gate: Wilson prints it duplex and runs it with a pencil**, the way
he ran First Light — does the face-down sheet actually work, are the writing rules tall enough,
is 3 em the right blank, is Sheet 3/4's split right. Fold his read into §3's numbers before any
code generalises them. ⚠ Nothing in Phase 0 is reusable code by design; it is the mock the plan
is checked against.

**Phase 1 — `make_pdf.py` (Sonnet).** Everything in §§3, 6. Per-lesson `[print]` table in the
sidecars (default + the L00 override). Sheet chunking caps. Both sizes. `--check`. **Gate:**
`--check` passes on all eleven; `lesson-2.pdf` is page-for-page what Phase 0 produced by hand;
`pdftoppm` one sheet front and back of Lesson 0 and Lesson 10 and *look at them* — the
letter sheet and the capstone are the two ends of the ramp.

**Phase 2 — wire in and ship (Sonnet/Haiku; one hard stop).** Links on the lesson page, `/`,
`/for-syriacists`; the bundle; a line on `/sources` saying the PDFs are generated from the same
records. Full render, then `npx vercel --prod` **from `learn/site/`** (⛔ production deploy —
"deploy? y/n"). Verify on the real domain by downloading `lesson-2.pdf` and opening it.

**Phase 3 — Wilson runs Lesson 0 and Lesson 1 on paper.** The two G2-passed lessons, now on the
medium they were originally written for (every lesson still says *you need: this document, a
pencil, a piece of paper*). What he finds goes into `SYRIAC-LANGUAGE-PILOT.md` as a ruling if it
is about pedagogy, into `print.css` if it is about paper.

Order: 0 before 1 (the mock is the spec; don't generalise an unrun layout) · 1 before 2 · 3 after
2 because a printed-from-the-live-site file is the thing being tested.

## 8. Execution tiers, and the burn

Sonnet throughout — every phase is pattern-following against machinery in the repo
(`make_learn.py`'s structure, `make_drill.py`'s compiled shape, the deploy notes, the web plan's
§6 footer). No authored prose: the only new sentences are sheet instructions ("write the sound and
the meaning"), the blank-page notice, and one link line, and those are written here. Rough burn:
Phase 0 ≈ 40–60K, Phase 1 ≈ 80–120K, Phase 2 ≈ 20K; two sessions. ⚠ 8 GB Mac: headless Chrome
is ~300 MB per process — the tool runs renders **serially**, never in parallel, and the build is
a thing to run while nothing else heavy is open. Playwright-Python (`pip install playwright` on
3.11; the browsers are already cached under `~/Library/Caches/ms-playwright`) is the one
upgrade if a 10-minute build becomes a nuisance — it is one process for all renders — and it is
*not* v1.

## 9. Rulings wanted — defaults are stated; a bare "go" takes all of them

1. **Sheet grain: four sheets per lesson** (Vocabulary · Forms · Half-a-line/One-word ·
   Finish/Whole/Drills), self-contained front+back each — vs. fewer, denser sheets. *Default:
   four; Phase 0 tests the split.*
2. **Vocabulary sheet carries both directions** (A: Syriac → sound + meaning; B: meaning →
   Syriac) on one front. *Default: yes.*
3. **Lesson 0's letter sheet gets a plain ruled "copy this letter" row per letter** — copying,
   not tracing, no stroke arrows; item 2 owns formation. *Default: yes, because a learner with a
   pencil and 22 letters will copy them anyway, and a rule under each is free.* Say no if it
   feels like it pre-empts item 2.
4. **Letter + A4, both, every lesson.** *Default: both.*
5. **Course bundle** (`chrestomathy.pdf`), linked from `/` and `/for-syriacists`. *Default: yes.*
6. **Noto in the PDF, Meltho never** (§4). *Default: yes; this one is a licence fact more than a
   preference.*
7. **The PDF pass is separate from `make_learn.py`'s default run** (§5). *Default: yes.*

## 10. Left out on purpose

Stroke-order / tracing sheets (item 2, its own session) · a designed "book" edition of the
course (the bundle is a concatenation, not a typeset reader; if Wroot Press ever wants *A Syriac
Chrestomathy* as a print title, that is a KDP project with its own conventions, not this) ·
per-lesson PDFs for the hand track (`paleography.app/<lang>` primers — same tool would do it; not
asked for) · fillable PDF form fields (paper is the point) · any change to lesson prose or sidecar
content · Playwright (§8) · Hebrew.
